# Zoho Inventory 1:1 Clone — Full Roadmap

## Context

The project already replicates Zoho Inventory's chrome faithfully (sidebar with trial card, header, home tabs Dashboard/Getting Started/Recent Updates/Announcements, dashboard widgets "Sales Activity" + "Inventory Summary", custom-views dropdowns, kebab menus, option cards) but has **no data layer and mostly stub bodies** — items list is `<div>test</div>`, forms are demos, 6 pages are placeholders. Goal: complete the clone 1:1 in **UI + function**, backed by **PostgreSQL + Drizzle ORM**, keeping the current **shadcn/Tailwind base with Zoho-look styling** (~90% visual match, not pixel-perfect).

Because this is many sessions of work, step 0 writes this roadmap to `docs/ROADMAP.md` with checkboxes so progress survives across sessions.

## Stack & conventions

- Existing: Next.js 16 (App Router, Turbopack), React 19, Tailwind 4, shadcn/ui, react-hook-form, zustand, lucide.
- Add: `drizzle-orm`, `drizzle-kit`, `postgres` (driver), `drizzle-zod`, `zod`, `@tanstack/react-table`, `@hookform/resolvers`, `sonner`, `date-fns`, `react-day-picker`.
- Data access: server components query Drizzle directly; mutations are **server actions** + `revalidatePath`. Numbering series (`ITEM-00001`, `SO-00001`…) from a `numbering_series` table.
- New deps + scripts in `package.json`: `db:generate`, `db:push`, `db:studio`, `db:seed`. `DATABASE_URL` in `.env` (assumes local Postgres `inventory_management` db).
- Routes: list `/office/<section>/<module>`, new `.../new`, detail/edit `.../[id]`.
- Forms: react-hook-form + zod (`drizzle-zod` schemas), shadcn `form.tsx`, floating-label `TextInput` (already in [components/form/text-input.tsx](components/form/text-input.tsx) — retheme its hardcoded M3 purple `#6750A4`/`#CAC4D0` to theme tokens).

## Data model (`db/schema/`, one file per domain)

- `org.ts` — `organization` (name, logo, address, currency, tax settings), `users` + `roles` (display/mock), `activity_log` (who/what/when for Recent Updates + record History tabs).
- `items.ts` — `items` (name, type enum inventory/non_inventory/service, sku, unit, brand, category, description, status), `item_groups`, `composite_items` + `composite_components`, `price_lists` + `price_list_items`, `categories`, `brands`, `units`.
- `warehouses.ts` — `warehouses`, `inventory_adjustments` + lines, `stock_counts` + lines, `transfer_orders` + lines, **`stock_movements` ledger** (source_type/source_id → every qty change flows through it; item stock-on-hand = ledger sum).
- `contacts.ts` — `contacts` (type customer/vendor, tabs: details, addresses, other details), `contact_persons`.
- `sales.ts` — `estimates`, `sales_orders`, `packages`, `shipments`, `deliver_challans`, `invoices`, `customer_payments`, `credit_notes`, `sales_returns` — each with `*_lines` child table (item, desc, qty, rate, discount, tax, amount, warehouse), `status` enum + `status_history`.
- `purchases.ts` — `purchase_orders`, `bills`, `vendor_payments`, `debit_notes`, `expenses`.
- `settings.ts` — `taxes` (+ group taxes), `currencies`, `numbering_series`, `templates`, `notification_prefs`, `automation_prefs`.

## Shared UI system (built once in Phase 0, reused by every module)

- [components/office/inventory/switch-view.tsx](components/office/inventory/switch-view.tsx) → generalize to `components/shared/switch-view.tsx` (controlled value/onChange).
- `components/shared/list-toolbar.tsx` — composes: **CustomViewsDropdown** (title + views + "+ New Custom View", from existing [items/page.tsx](app/(back-office)/office/inventory/items/page.tsx) dropdown pattern), **New** button, SwitchView, **KebabMenu** (Sort by submenu / Import / Export / Preferences / Refresh List — existing dropdown-menu.tsx already supports submenus).
- `components/shared/data-table.tsx` — TanStack Table: checkbox column, sortable headers, sticky header, **bulk-action bar** (Activate/Deactivate/Delete), row kebab menu, footer pagination.
- `components/shared/empty-state.tsx` — generalizes [components/office/inventory/option-card.tsx](components/office/inventory/option-card.tsx) (title/icon/description/CTA cards grid).
- `components/shared/page-form-shell.tsx` — New/Edit full-page pattern: `h2` title + X-close + sticky Save/Cancel footer + tab nav (matches existing items/new pattern).
- `components/shared/detail-page.tsx` — record detail: title + status badge + action dropdown (Edit/Delete/Copy/converts) + Overview/Transactions/History tabs.
- shadcn adds: `table, select, checkbox, radio-group, popover, command, form, tabs, badge, textarea, alert-dialog, calendar, progress, sonner`.
- Theme: load **Roboto** via `next/font` (Zoho's font — replaces Inter, also fixes unused `font-roboto` reference), keep orange primary + slate chrome, keep dark-mode toggle as an extra.

## Phases

### Phase 0 — Foundation
1. Write `docs/ROADMAP.md` (this plan, checklisted) + commit baseline.
2. Install deps, `drizzle.config.ts`, `db/index.ts`, full schema, `db:push`, seed script (sample org, 12 items, 2 groups, warehouses, customers/vendors).
3. Fix existing mismatches found in comparison: sidebar duplicate "Integration" → "Reports" ([sidebar.tsx:70](components/office/sidebar.tsx)), items page title "All Item Groups" → "All Items" + per-module kebab labels (Import/Export **Items**), `window.location.href` → `Link`/`useRouter`, itemgroups List Toggle → shared SwitchView, wire `useView` zustand store to view toggle.
4. Build all shared components above; wire `/office/home` client-redirect into server `redirect()`.

### Phase 1 — Items domain
- **Items list**: real table (Item Name, Code, Purchase Price, Selling Price, Stock on Hand, Unit, Status), 12 custom views (All/Active/Ungrouped/Low Stock/Inventory/Non-Inventory/Services/Inactive/…), filter dropdown, bulk actions, pagination. Replaces `<div>test</div>`.
- **New/Edit Item** form tabs: Item Details (name, type, SKU, unit, brand, category, description), Buy Info (vendor, cost, opening stock + warehouse + reorder level), Sell Info (selling price, wholesale, tax). Detail page with Overview/Transactions/History.
- **Item Groups**: list (name, # items, desc) + New form (name, variant attributes, description). **Composite Items**: list + form (component item picker + qty, computed cost). **Price Lists**: list + form (currency, markup/markdown, per-item rows).
- Sidebar Inventory section fully live; option-cards CTA buttons link to the four modules.

### Phase 2 — Stock operations
- **Inventory Adjustments**: list (date, reference, reason, status) + New (warehouse, reason, adjusted-qty lines) → ledger entries. **Stock Counts**: New (system vs counted) → generates adjustment. **Warehouses**: list + form + detail. **Transfer Orders**: New (from/to warehouse, lines) with Create→Mark Shipped→Mark Received workflow writing movements at both ends.

### Phase 3 — Sales
- **Customers** (contacts): list + form (Contact Details/Address/Other Details tabs) + detail with transactions tab.
- **Estimates** (Draft→Sent→Accepted/Declined/Expired, convert to SO/Invoice) → **Sales Orders** (Draft→Confirmed→Packed→Shipped→Invoiced; actions Create Package/Shipment/Invoice) → **Packages** → **Shipments** (courier, tracking) → **Invoices** (Draft/Sent/Partially Paid/Paid/Overdue; Record Payment) → **Customer Payments**, **Credit Notes**, **Deliver Challans**, **Sales Returns**. All lists/forms follow shared patterns; statuses + numbering real; dashboard "Sales Activity" now counts real records.

### Phase 4 — Purchases
- **Vendors** (mirror customers), **Expenses**, **Purchase Orders** (Receive Items → stock in), **Bills** (from PO; Record Payment), **Vendor Payments**, **Debit Notes**.

### Phase 5 — Home, Reports, Documents
- **Getting Started**: checklist cards + progress (add first item/customer/invoice, complete org profile) driven by real data. **Recent Updates** = activity_log feed; **Announcements** page.
- **Reports**: index grouped (Inventory: Stock Summary/Valuation/History/Low Stock; Sales: by Customer/Item; Purchases: by Vendor/Item; Payments) — filterable tables + CSV export.
- **Documents**: per-record attachments (local fs under `.data/uploads/`, list + upload UI).
- Record History tabs write to `activity_log` from server actions.

### Phase 6 — Settings & org
- Settings index (search + grouped cards like Zoho): Organization Profile, Taxes, Currencies, Units, Categories, Brands, Numbering Series, Users & Roles (mock invite + permission matrix), Templates (email/print HTML), Notifications, Automation, Integrations (UI-only "Enable Now" states).

### Phase 7 — Cross-cutting polish
- Global search via command palette (`/` shortcut — matches the existing "( / )" placeholder), Quick Create menu on header + button, notifications dropdown, profile menu, functional sidebar collapse, toasts (sonner) on every action, alert-dialog delete confirms, empty states everywhere, loading skeletons, error boundaries.
- Final QA: every list/form side-by-side vs Zoho Inventory screenshots; `build` + `lint` green.

## Reuse (don't rebuild)

- `components/ui/*` (dropdown-menu with submenus, sheet, scroll-area, tooltip, button, avatar…), `cn()` in [lib/utils.ts](lib/utils.ts), next-themes provider, zustand `useView`, Toolbar/Header/OptionCard/SwitchView inventory components, the New-page X-close + `router.back()` pattern.

## Verification (every phase)

1. `npm run db:push` → `npm run dev` → `npm run build` + `npm run lint` all green.
2. Browser-walk each new route (200s + visually matches Zoho layout) — dev server + curl + screenshots.
3. Data-flow test: create item → appears in list & views; adjustment/transfer changes stock-on-hand via ledger; SO→Package→Shipment→Invoice chain updates statuses; payment flips invoice to Paid.
4. Tick off items in `docs/ROADMAP.md` and commit per phase, so the next session resumes exactly where this left off.

## Out of scope (noted, not planned)
Real email/SMS sending, payment gateways, external integrations (Shopify/Amazon etc.), e-invoicing compliance, multi-org auth.
